# Point, segment and polygon contact assembly

`CollisionPointContacts` assembles a pair containing at least one point. The other feature can be a point, segment, triangle, box face or cylinder cap. `CollisionSegmentContacts` handles two segments, producing one pair for crossings, disjoint intervals and endpoint touches, or two ordered pairs for parallel overlap.

`CollisionPolygonSegmentContacts` handles a segment against a triangle, box face or cylinder cap in either order. It clips segment bounds against the polygon's ordered edges. Separated parallel edges retain a distinct correction path: two corrected pairs can supply a replacement contact normal, while a collapsed interval produces one pair and updates both endpoint classifications. A zero-length segment inside a face retains two coincident pairs.

`CollisionFaceClipContacts.TryAssemble` clips a quadrilateral against a triangle or another quadrilateral. It appends inclusive edge intersections first, then strictly interior vertices from each face, projecting each pair onto both actual face planes. It preserves repeated boundary contacts, feature classifications and unused output slots. A false return resets the count to zero and requests the general polygon fallback; it does not mean the shapes have no contact. `CollisionPolygonContacts` supplies the general fallback and handles the other ordered polygon pairs. It retains inside vertices and edge crossings; separated faces select the closest feature pair and may replace the contact normal. `CollisionFeatureContacts` dispatches all point, segment and polygon combinations through these routines.

Inputs use the 144-word feature layout from [primitive feature selection](SHAPE-FEATURES.md). Both feature buffers are mutable: endpoint and edge selection update their packed primary classifications. Segment clamping uses strict bounds, and parallel endpoint selection has distinct classification updates. Polygon clamping retains the first equally violated edge. Other feature words remain unchanged.

The contact buffer requires 136 words. First-side positions begin at word 0, second-side positions at word 64, and the count occupies word 132. A separated polygon/segment edge can set word 133 and write its replacement normal at word 128. The caller initializes word 133 to zero before dispatch. Other unused point slots and metadata remain unchanged. The supplied direction retains its original arithmetic; it is not normalized. Invalid buffer sizes and unsupported feature kinds fail before modifying the contact buffer. General polygon assembly stages its output and rejects more than sixteen pairs without committing any changes. This deliberately prevents buffer corruption for nearly coincident boundaries; it does not silently truncate or deduplicate contacts.

## Validation

The connected engine replay runs primitive feature selection followed by contact assembly. All 1,419 supported cases match 1,016,004 exact words, including input-feature mutations and untouched output storage. Cases include both pair orders, polygon interior/edge/vertex contacts, adjacent endpoint boundaries, parallel and nearly parallel segments, crossing and separated segments, and zero-length segments.

Fifteen unit cases cover independent geometric and state invariants: contact order, retained separation, endpoint classifications, stable edge ties, overlap counts, strict endpoint touches, degenerate segments and output preservation. Original execution covers every instruction in the six routines used by these branches; that is not arbitrary-input or full-gameplay coverage.

Polygon/segment assembly adds 1,766 native cases and 755,848 exact assembly words. The connected feature-selector and assembly path matches 1,264,456 words. Cases cover both orders, all three polygon kinds, short and long segments, separated corners, nearly parallel edges and tilted segments. All 588 instructions in its two routines are exercised. The 1,756 new original cases repeat exactly with reversed order and poisoned scratch state. Seven additional unit cases check clipping, plane separation, replacement normals, endpoint classifications, degeneracy and validation without mutation.

Specialized face clipping adds 2,220 complete buffer comparisons and 300 fallback decisions, matching 952,980 native values. A composed feature-selector check adds two complete cases and two fallback decisions across 2,014 values. All 1,319 instructions in the two specialized clipping paths are exercised. Reversed-order, poisoned-scratch replay matches all 2,524 supplied cases. Seven unit cases check pair order, contained faces, touching edges, retained duplicate intersections, fallback and invalid inputs without mutation. Fallback cases compare the need for fallback, not the unimplemented contacts it would produce.

General assembly now matches 2,154 supplied polygon cases across 921,912 exact words, including closest-feature flags and replacement normals. Six additional nearly coincident octagon cases are explicitly rejected because their contact lists exceed the fixed layout. Another 2,568 comparisons confirm that rejection preserves caller buffers; these six are not counted as parity passes. All 2,160 original cases repeat under reversed order and poisoned scratch state. The complete shape-selector and dispatcher chain now passes all 1,439 earlier cases with no exclusions across 1,030,324 exact words.

The combined original execution covers 1,320 of 1,328 dispatcher instructions and all 235 closest-polygon helper instructions. The eight uncovered instructions handle nonpositive polygon counts, which valid polygon kinds cannot reach. Eight new unit cases cover contained faces, separated faces, normal direction, invalid kinds and transactional overflow rejection.

## Remaining work

[Pair-axis selection](PAIR-AXES.md) now drives 80 connected cases through the general, sphere, box and triangle/box branches. Another 45 cases require cylinder-specific axes. Final round-radius expansion, normal orientation, triangle filtering, full manifold generation and live map integration remain unfinished. The replay uses synthetic descriptors and the retained arithmetic profile; it does not establish hardware or complete gameplay parity.
